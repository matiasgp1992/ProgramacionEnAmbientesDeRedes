Preguntas HTTP

1) ¿Sobre qué protocolo binario está montado el protocolo HTTP?

El protocolo HTTP tradicionalmente se ejecuta sobre el protocolo de capa de transporte TCP (un protocolo orientado a la conexión y fiable). En versiones modernas como HTTP/2, el protocolo en sí pasa a ser binario pero mantiene la capa TCP debajo. Por su parte, la versión HTTP/3 está montada sobre QUIC, un protocolo que opera sobre UDP para lograr mayor velocidad e independencia de paquetes.

2) ¿Cuáles son los clientes http y los servidores http más utilizados?

Clientes HTTP:

  • Navegadores web (Chrome, Firefox, etc.).
  • Herramientas de consola como cURL.
  • Librerías nativas de diversos lenguajes de programación (Java, C#, Python, etc.).

Servidores HTTP:

  • Servidores Web como Apache, Nginx o servidores basados en intérpretes/entornos como Tomcat (JVM) o PHP.

3) ¿Qué verbos admite un comando en el requerimiento HTTP?

Los métodos o verbos HTTP utilizados en la línea inicial de la petición incluyen:

  • GET: Utilizado para operaciones de solo lectura.
  • POST: Utilizado habitualmente para enviar datos y actualizar/procesar recursos.
  • PUT: Utilizado para crear recursos en un servidor.
  • DELETE: Utilizado para eliminar recursos en el servidor.
  • CONNECT: Utilizado por servidores Proxy para establecer túneles de comunicación.

4) ¿Qué contenido lleva el body de un requerimiento HTTP?

El cuerpo (body) de una petición puede contener datos en cualquier formato:

  • Datos ingresados por un usuario en los campos de un formulario.
  • Archivos enviados mediante procesos de carga o upload.

5) ¿Qué diferencia existe entre un URL y un URI?

URI (Uniform Resource Identifier): Es la identificación del recurso específico dentro del servidor, junto con sus parámetros o cadenas de consulta (por ejemplo, path_al_recurso/index.html?var1=valor1).

URL (Uniform Resource Locator): Es el conjunto completo necesario para localizar el recurso en la red, formado por el protocolo, el host o dominio, el puerto y la URI (ejemplo: http://nombreHost.dominioHost:puerto/URI).

6) ¿Como se almacena información relacionada con las respuestas http?

Cookies: El servidor puede enviar un encabezado Set-Cookie en la respuesta con pequeños bloques de información que el navegador guarda en la memoria del cliente y reenvía en futuras peticiones al mismo origen.

Caché del navegador: Los archivos y recursos recibidos pueden ser almacenados en la memoria/disco del navegador según lo determinen cabeceras de control como Cache-Control o Expires.

7) ¿Qué significa HTTP sobre conexiones preexistentes?

Significa reutilizar una misma conexión TCP abierta (mediante el encabezado Connection: keep-alive en HTTP/1.1) para realizar múltiples peticiones y respuestas consecutivas sin necesidad de cerrar y abrir un socket nuevo por cada elemento solicitado.

8) ¿Qué significa Virtual hosting?

Es la capacidad de un servidor web para atender y responder a múltiples dominios o nombres de host alojados bajo una misma dirección IP pública. Para ello, el cliente incluye de forma obligatoria el encabezado Host: en la petición HTTP para indicarle al servidor a cuál dominio específico desea acceder.

9) ¿Qué significa Cache por etag?

Es un mecanismo de validación de caché basado en un identificador único o "huella digital" (hash / fingerprint) que el servidor asigna a cada archivo.

  • Si el recurso está en la memoria del cliente, el navegador envía el encabezado If-None-Match: <ETag>.
  • El servidor compara el ETag recibido con el actual del recurso: si no ha cambiado, responde únicamente con el código 304 Not Modified sin volver a transferir el archivo completo, optimizando el ancho de banda.

10) ¿Porque el HTTP se considera STATE LESS?

Se considera stateless porque cada transacción de petición y respuesta es independiente. Una vez cerrada o finalizada la comunicación, el protocolo por sí mismo no guarda un registro de la interacción previa ni mantiene el estado de la aplicación entre peticiones sucesivas.

11) ¿Qué nueva versión de HTTP se está usando para mejorar la velocidad de la WEB?

Para mejorar la velocidad se utiliza HTTP/2 (que incluye multiplexación de requerimientos, frames binarios, compresión de cabeceras y Server Push) y progresivamente HTTP/3.

12) ¿Como va a mejorar el comportamiento de una aplicación WEB en ambientes ruidosos o de débil conexión?

A través de HTTP/3 sobre el protocolo QUIC (montado sobre UDP). QUIC permite manejar conexiones más cortas, eficientes e independientes, ofreciendo una gran capacidad de reconexión inmediata frente a la pérdida de paquetes o caídas causadas por interferencias, exceso de tráfico o baja cobertura móvil/inalámbrica.
